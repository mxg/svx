\chapter{Traits}
\section{Traits Classes}
\noindent\small\textit{File: \texttt{core/src/containers/traits.svh}}\par

The traits system provides per-type constants and static functions used by all parameterized containers and algorithms. Every traits class defines an \texttt{empty\_t} typedef, an \texttt{empty} constant, and static \texttt{equal()}, \texttt{compare()}, and \texttt{sort()} functions. The base class is \texttt{void\_traits}; scalar integer families derive from \texttt{base\_int\_traits}.

\section{Permutation Iterators}
\noindent\small\textit{File: \texttt{core/src/iterators/permute\_iterators.svh}}\par

Iterators that generate all permutations of a bound vector without modifying it. An internal index ordering tracks the current permutation; the bound vector itself is never changed. The original ordering of the bound vector is permutation~0. A vector of length~$n$ has $n!$ permutations. \texttt{get\_nth(n)} returns the \texttt{n}th element of the current permutation; \texttt{get\_permutation\_vector()} returns the current element ordering. \texttt{permute\_iterator} traverses all permutations sequentially in both directions; \texttt{permute\_random\_iterator} jumps to a randomly chosen permutation. \section{lexer\_core --- Lexical Analyzer}
\noindent\small\textit{File: \texttt{core/src/lexer/lexer\_core.svh}}\par

Breaks a string into tokens. Call \texttt{start()} with the string to analyze, then call \texttt{get\_token()} repeatedly until it returns \texttt{TOKEN\_EOL}. After each token, \texttt{get\_lexeme()} returns its text and, for numeric tokens, \texttt{get\_token\_descriptor()} returns details such as size, base, and sign. Whitespace between tokens is skipped. The lexer does not handle comments.

Numeric constants follow SystemVerilog conventions without the apostrophe, which command shells treat specially: an optional sign, an optional decimal size, a base letter (\texttt{b}, \texttt{o}, \texttt{d}, or \texttt{h}, either case), and digits, e.g. \texttt{32h7fff\_624c} or \texttt{-100}. Underscores may appear between digits but not as the first character. Real constants use a decimal point and/or an exponent, and a number followed by a time unit is returned as \texttt{TOKEN\_TIME}.

\part{UVM Utilities}

\chapter{Command Line Processor}
\section{Overview}
\noindent\small\textit{File: \texttt{uvm/src/README-cl.md}}\par

The command line processor recognizes plusargs --- arguments of the form \texttt{+name} or \texttt{+name=value} --- validates each value against a table of registered options, converts it to the option's type, and puts it into the UVM resource database under the scope \texttt{CL::}. The table gives a single place to find every option a testbench accepts.

The use model has three steps, all performed before \texttt{run\_test()} so that every phase, including \texttt{build\_phase}, can read the values:

\begin{enumerate}
\item Register each option with \texttt{cl\#(T)::add()} or \texttt{cl\#(T)::add\_with\_default()}. Registration can happen anywhere --- any module, package, or class --- and in any order.
\item Call \texttt{cl\_parse::get().parse()} once.
\item Read values with \texttt{uvm\_resource\_db\#(T)::read\_by\_name("CL::", name, val)}.
\end{enumerate}

A \texttt{+name} without a value turns on a \texttt{bit} option. Numeric values may be sized and based, SystemVerilog style but without the apostrophe (e.g. \texttt{32h7fff\_624c}), and must fit the option's type. \texttt{string} values are taken as written, without being broken into tokens. Arguments that are not registered options --- simulator options, UVM options, other plusargs --- are skipped. If any registered option has an invalid value, the parser reports an error and publishes no command line values; UVM then stops the run at the end of elaboration.

Supported types are \texttt{bit}, \texttt{byte}, \texttt{shortint}, \texttt{int}, \texttt{longint}, their \texttt{unsigned} forms (including the \texttt{int8\_t} ... \texttt{uint64\_t} aliases), \texttt{real}, and \texttt{string}.

\section{Option Descriptors and Instances}
\noindent\small\textit{File: \texttt{uvm/src/cl\_opt\_desc.svh}, \texttt{uvm/src/cl\_opt\_instance.svh}}\par

Each registered option has a descriptor; each occurrence on the command line produces an instance. Descriptors form a three-level hierarchy: a non-parameterized base used to manage descriptors polymorphically, \texttt{cl\_opt\_desc\#(T)} which supplies the value type, and leaf classes that implement type-specific parsing and conversion. Adding support for a new kind of value means adding a leaf class and a factory entry; the parser itself does not change.

\chapter{Pipelined Testbenches}
\section{Pipe Stages}
\noindent\small\textit{File: \texttt{uvm/src/pipe\_stage\_base.svh}, \texttt{uvm/src/pipe\_stage.svh}}\par

Base classes for building testbenches as a chain of stages. Each stage owns a sequencer and exposes it through \texttt{seq\_item\_export}; the next stage pulls items through its \texttt{seq\_item\_port}. A stage processes each item in \texttt{process\_item()} and, unless it is the last stage, sends the item downstream with \texttt{sqr.execute\_item()}. Each stage sets its \texttt{done} flag when it has no more work, so the environment can end the test when every stage is done.
